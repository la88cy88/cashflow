# 打工人现金流

> 把时间变成看得见的钱。

一个纯前端、零依赖、可离线使用的实时工资可视化 PWA。打开手机就能看到今日工资按毫秒持续增长；锁屏、切后台、刷新或重新打开后，一律按真实时间重新校准，绝不丢进度。

**在线访问**：https://la88cy88.github.io/cashflow/ （iPhone 用 Safari 打开，可添加到主屏幕）

---

## 为什么这个数字可信

- 金额永远是 `f(今日计划, Date.now())` 的纯函数结果：不使用定时器累加、不缓存金额、不依赖页面存活时长。
- 主循环用 `requestAnimationFrame` 高频刷新；`visibilitychange` / `pageshow` / `focus` 与每秒校准负责在回到前台时立即重算。
- 显示到小数点后 6 位，使用等宽数字字体；金额被严格限制在 `[0, 今日工资]`。
- 数据只存在本机 LocalStorage：无服务器、无 API、无账号、无第三方 CDN、无统计埋点。

## 功能

- 今日工资 / 上班 / 下班 / 午休时长 / 午休开始时间，每天独立保存
- 常用默认值，跨天自动沿用，可随时单独修改某一天
- 跨午夜班次：下班时间早于上班时间时自动识别为「次日下班」
- 午休期间工资暂停增长，状态显示「休息一下」
- 四种工作状态、完成百分比、进度条、已工作 / 剩余时间
- 每小时 / 每分钟 / 每秒收入与有效工作总时长
- 逐位数字滚动、25/50/75/100% 里程碑金币动画、目标达成庆祝动画（可一键关闭）
- 随机激励语、浅色 / 深色 / 跟随系统主题
- 最近 7 天数据概览、JSON 导出备份与恢复、清空数据
- PWA：离线可用、添加到 iPhone 主屏幕、桌面浏览器可用

## 本地运行

需要 Node.js ≥ 18（仅用于起静态服务器和跑测试，应用本身不需要 Node）。

```bash
npm start          # 启动 http://localhost:4173
npm test           # 36 项单元 / 边界测试
npm run verify     # 语法、DOM 引用、PWA 资源、敏感信息扫描
npm run smoke      # 真实 Chrome 端到端测试 + iPhone 尺寸截图
npm run icons      # 重新生成 PWA 图标（仅需 Python 3）
```

项目零依赖，**不需要 `npm install`**。

## iPhone 添加到主屏幕

1. 用 **Safari** 打开在线地址（不要用微信内置浏览器或 Chrome 添加到主屏幕）。
2. 点底部中间的「分享」按钮。
3. 下滑找到「添加到主屏幕」。
4. 名称改成「现金流」，点「添加」。
5. 从主屏幕图标打开：全屏无地址栏，支持离线使用。

> ⚠️ iOS 上「主屏 Web App」与 Safari 的本地存储是相互独立的空间。首次从主屏打开时，按自己的计划重新设置一次即可；之后数据会稳定保留在这个 App 内。换机或清缓存前，建议用「概览 → 导出备份文件」保存一份 JSON。

## 修改今日工资和上下班时间

1. 点首页右上角齿轮图标，或首页底部「编辑今日计划」。
2. 修改「今日工资」「上班时间」「下班时间」；有午休就填「午休时长（分钟）」和「午休开始」。
3. 表单下方实时预览有效工作时长与折合时薪；输入不合法会标红并说明原因。
4. 点「保存今日计划」→ 立即按真实时间重新结算，数字马上变化。
5. 工作已开始时修改会弹出二次确认，避免误触。
6. 「保存为默认值」只更新以后新的一天的模板；「恢复默认设置」把默认值填回表单，需再点保存才生效。
7. 设置页「修改默认计划」可直接编辑模板。

工作开始之后依然允许随时改；改完只更新当天记录，其他日期不受影响。

## 计算原理

```
有效工作总毫秒 = (下班 - 上班) - 午休时长
每毫秒工资     = 今日工资 ÷ 有效工作总毫秒
今日实时工资   = 今日工资 × 已完成有效工作毫秒 ÷ 有效工作总毫秒
```

时间轴先把班次 `[上班, 下班)` 减去午休区间 `[午休开始, 午休结束)`，得到最多两段「有效工作段」；已完成毫秒是各段与 `[上班, 当前时刻]` 的交集之和。跨午夜、午休、中途改计划都用同一套逻辑精确处理。

持久化层只保存 `YYYY-MM-DD` 日期键和 `HH:mm` 钟表时间，**不保存绝对时间戳**；每次计算按设备当前本地时区现场解析，因此跨时区旅行不会让当天数据错位或被重置。

## 边界处理

| 场景 | 行为 |
| --- | --- |
| 上班时间早于当前时间 | 打开即显示已产生的工资 |
| 当前时间早于上班时间 | 显示 `¥0.000000` 与「准备上班」 |
| 当前时间晚于下班时间 | 显示完整今日工资与「今日工资到账」 |
| 修改工资 | 立即按新工资重算 |
| 修改上下班时间 | 重新计算工作时长、时薪与进度 |
| 跨午夜班次 | 自动识别为次日下班；凌晨仍归属前一天的班次，下班后才切到新的一天 |
| 午休期间 | 金额冻结，状态切换为「休息一下」 |
| 锁屏 / 切后台 / 刷新 / 重开 | 按 `Date.now()` 重新计算，金额不丢不跳 |
| 手机时区变化 | 按新本地时间解析同一份日期键与钟表时间 |
| 工作时长为 0 / 输入非法 | 禁止计算，显示明确错误提示 |
| 金额上限 | 永远不超过设定的今日工资 |

| --- | --- |
| `prefs` | 主题、动画开关、货币符号 |

## 部署与后续维护

站点是纯静态文件，当前通过 **GitHub Pages 从 `main` 分支根目录直接发布**，无需构建步骤。

**更新代码**

```bash
git add .
git commit -m "描述改动"
git push origin main
```

推送后 Pages 十几秒内自动更新。

**切换到 GitHub Actions 发布（可选）**

仓库的 `tools/deploy-pages.yml.example` 保留了完整的 GitHub Actions 部署配置（只打包 `index.html`、`manifest.webmanifest`、`sw.js`、`css/`、`js/`、`icons/`）。切换步骤：

1. 把该文件移动到 `.github/workflows/deploy.yml`；
2. 仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**；
3. 推送。

> 初次部署使用的访问令牌只有 `repo` 权限、缺少 `workflow` 权限。GitHub 按目录路径检查：只要是 `.github/workflows/` 下的文件（连 `.example` 后缀也一样），缺少 `workflow` 权限的令牌都会推送失败。因此配置暂存在 `tools/` 下、站点改用等效的分支发布。两种方式产出的线上站点完全一致，分支发布对纯静态站点还少一步构建。

**改了静态资源时**：同时把 `sw.js` 顶部的 `VERSION` 递增（例如 `v1.0.1`），否则用户端可能仍用旧缓存。前端检测到新版本会显示「有新版本可用 → 刷新」提示条，点一下即可切换。

**改了图标时**：`npm run icons` 重新生成 PNG，然后提交 `icons/`。

## 常见问题

**Q：金额不动？** 检查当前时间是否在设定的工作时段内；上班前固定为 0，下班后固定为全额，午休中会暂停。

**Q：刷新后庆祝动画又放了一遍？** 不会，里程碑按日期持久化。只有主动修改当天计划才会重置里程碑。

**Q：换手机怎么迁移？** 旧设备「概览 → 导出备份文件」，新设备「概览 → 从备份恢复」。

**Q：为什么主屏 App 里的数据和 Safari 不一样？** iOS 把两者当作独立存储区，这是系统行为。选定一个入口长期使用即可。
